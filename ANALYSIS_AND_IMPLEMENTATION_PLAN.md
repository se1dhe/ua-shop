# Комплексний аналіз та план реалізації: Маркетплейс Цифрових Товарів та Ігрових Цінностей (Модель FunPay)

---

## 1. Концепція проекту: Український FunPay / Gumroad гібрид

Платформа об'єднує два ключових сегменти:
1. **Ігрові цінності та P2P послуги (модель FunPay)**:
   - Ігрова валюта (WoW Gold, PoE Orbs, Roblox Robux, Brawl Stars гемси, FC Coins тощо).
   - Скіни та предмети (CS2, Dota 2, Rust, TF2).
   - Акаунти та підписки (Steam, Epic, Discord Nitro, Spotify, PlayStation).
   - Бустинг та прокачка ігрових персонажів.
2. **Цифровий контент та інструменти (модель Gumroad/Envato)**:
   - Софт, скрипти, Telegram-боти, плагіни, ключі активації Windows/Office/VPN.
   - Дизайн-пакети, 3D-моделі, пресети.

## 2. Архітектура безпечної P2P угоди (Escrow Engine)

```
[Покупець]                            [Сервіс CyfraHub]                        [Продавець]
    |                                         |                                     |
    |---- 1. Оплата замовлення -------------->|                                     |
    |    (Monobank / Apple Pay / Crypto)      |-- Заморожування коштів (HOLD) ----> |
    |                                         |-- Створення захищеного чату ------> |
    |                                         |-- Сповіщення в Telegram Bot ------> |
    |                                         |                                     |
    |<=========== 2. P2P Чат у реальному часі (WebSocket / Telegram) ==============>|
    |                                         |                                     |
    |                                         |<--- 3. "Товар передано в грі/чаті" -|
    |                                         |                                     |
    |---- 4. "Підтвердити отримання" -------->|                                     |
    |                                         |-- Розморожування коштів ----------> |
    |                                         |-- Нарахування на баланс продавця -> |
    |                                         |   (за вирахуванням комісії 7-12%)   |
    |                                         |                                     |
    |-- (Або: "Відкрити спір/арбітраж") ----->|                                     |
    |                                         |-- Блокування виплати                |
    |                                         |-- Підключення модератора            |
```

### Два типи виконання замовлення:
1. **Автоматична миттєва видача (Instant Auto-Delivery)**:
   - Для цифрових ключів, файлів, ліцензій, попередньо завантажених акаунтів.
   - Користувач оплачує $\to$ система відразу видає секретний ключ/файл з бази даних або S3, відправляє дублікат у Telegram-бот.
2. **Ручна P2P Escrow угода (Manual P2P Trade)**:
   - Для ігрової валюти, скінів у Steam, бустингу.
   - Покупець оплачує $\to$ гроші холдуються $\to$ відкривається чат замовлення $\to$ продавець передає цінності в грі $\to$ покупець підтверджує $\to$ кошти зараховуються продавцю.

## 4. Стек Технологій та Архітектура (SOLID)

### 4.1. Бекенд: Java 21 + Spring Boot 3
- **Модулі згідно з SOLID**:
  - `domain`: Сутності `User`, `Wallet`, `Transaction`, `Product`, `Order`, `ChatMessage`, `Dispute`.
  - `application`:
    - `OrderEscrowService` (Single Responsibility: життєвий цикл угоди: CREATED $\to$ PAID_HOLD $\to$ TRANSFERRED $\to$ COMPLETED / DISPUTED $\to$ REFUNDED).
    - `WalletLedgerService` (Double-entry бухгалтерія: фіксація кожної копійки, баланс доступний, баланс у холді, історія транзакцій).
    - `ChatService` (Обмін повідомленнями через WebSocket STOMP + збереження в БД).
  - `infrastructure`:
    - `payment`: Стратегії `PaymentGateway` (`MonobankMonoPayGateway`, `CryptoPayGateway`).
    - `telegram`: `TelegramNotificationAdapter` (сповіщення про замовлення, повідомлення з чату в TG, кнопки підтвердження).
    - `storage`: `CloudflareR2StorageService` для цифрових файлів та скріншотів доказів передачі товарів.

### 4.2. Фронтенд: Tauri v2 (macOS, iOS, Android) + Web
- Єдина кодова база: React 19 + TypeScript + Vite + Tailwind CSS v4 + Shadcn UI.
- Білдиться як Web SPA для браузера та пакується Tauri v2 у нативні додатки macOS, iOS та Android.
- Локалізація: `react-i18next` (UA / EN).
- Реальний час: WebSocket STOMP клієнт для чату угод та миттєвих звукових сповіщень про нові замовлення.

### 4.3. Інфраструктура та Деплой: Railway
- **Зупинка старого бьюти-шопу**: Очищення ресурсів або зупинка контейнера у Railway.
- **Нова конфігурація**:
  - `PostgreSQL 16` (Railway Managed Database)
  - `Redis 7` (Railway Managed Redis для кешування, блокувань та WebSocket сесій)
  - `Backend Container` (Spring Boot 3 multi-stage Dockerfile)
  - `Frontend Web Container` (Nginx / Cloudflare Pages / Railway static)

## 5. Дорожня карта реалізації (Roadmap)

1. **Фаза 1: Railway оточення та аутентифікація CLI**:
   - Авторизація у Railway CLI.
   - Зупинка сервісу бьюти-шопу.
   - Створення проекту та підключення PostgreSQL 16 і Redis.
2. **Фаза 2: Архітектура БД (Escrow, Wallet Ledger, Chat, Catalog)**:
   - Створення Flyway міграцій для користувачів, гаманців, товарів, ігор/категорій, замовлень, чатів та арбітражу.
3. **Фаза 3: Ядро Java Spring Boot бекенду**:
   - Реалізація Wallet & Ledger з транзакційною безпекою (ACID).
   - Інтеграція Escrow життєвого циклу замовлень.
   - Реалізація WebSocket STOMP чату.
   - Інтеграція Monobank Acquiring API для поповнення та оплат.
4. **Фаза 4: Telegram Bot зв'язка**:
   - Інтеграція бота з чатом угод (продавець отримує повідомлення покупця в Telegram і може відповісти).
5. **Фаза 5: Кросплатформний фронтенд (Tauri v2 + Web) UA/EN**:
   - Головна сторінка з іграми, категоріями, фільтрами серверів/фракцій (як на FunPay).
   - Торговий термінал (інтерфейс активної угоди з чатом та кнопками дій).
   - Кабінет продавця (управління лотами, таблиця цін, вивід коштів).
6. **Фаза 6: Деплой на Railway та верифікація**.
